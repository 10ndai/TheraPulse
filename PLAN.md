# TheraPulse Implementation Plan

## Context

TheraPulse is a web-based mental health platform that digitizes therapy workflows for Zimbabwean therapists and their clients. It replaces pen-and-paper tools (worksheets, assessments, session notes, progress tracking) with digital equivalents, enabling remote care continuity across borders (Zimbabwe + diaspora). This is a greenfield project for a bootstrapped 2-person team. **Mental health data is among the most sensitive data categories and will be heavily regulated** — security is the #1 priority across every decision.

**What we're building in this step:** The project foundation — CLAUDE.md rules file and phased ticket plan for the full MVP build.

---

## Tech Stack Decisions

| Component       | Choice                                                                      | Rationale                                                                                                                            |
| --------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Frontend**    | Next.js 15 (App Router) + TypeScript                                        | RSC support, SSR, best React ecosystem                                                                                               |
| **UI Library**  | shadcn/ui + Tailwind CSS + Radix UI                                         | WCAG 2.1 AAA accessibility, zero-runtime (CSP-safe), <120KB gzipped, full RSC support                                                |
| **Backend API** | NestJS + TypeScript                                                         | Centralized security (guards, interceptors, pipes), mature healthcare patterns, audit logging via middleware, proven RLS integration |
| **Database**    | PostgreSQL + Prisma ORM                                                     | ACID compliance, RLS, pgAudit, field-level encryption via pgcrypto, JSONB for flexible schemas                                       |
| **Auth**        | Custom JWT (access + refresh tokens) + TOTP 2FA                             | No vendor lock-in, full control over token lifecycle, 2FA mandatory for therapists                                                   |
| **Validation**  | Zod (shared package)                                                        | Single source of truth for API + frontend validation                                                                                 |
| **Testing**     | Vitest (unit/integration) + Playwright (E2E) + Testing Library (components) | Fast TDD feedback loop, 80%+ coverage enforced                                                                                       |
| **Monorepo**    | Turborepo                                                                   | `apps/web`, `apps/api`, `packages/shared`                                                                                            |
| **Hosting**     | AWS Africa (Cape Town) or Azure South Africa                                | Closest major cloud region for data residency                                                                                        |
| **CI/CD**       | GitHub Actions + Semgrep SAST + npm audit                                   | Automated security scanning on every PR                                                                                              |

## Database Schema (11 tables)

1. **`users`** — id, email, password_hash, role (ADMIN/THERAPIST/CLIENT), status, totp_secret (encrypted), totp_enabled
2. **`therapist_profiles`** — user_id, name, bio, specializations[], qualifications[], license_number, languages[], city, province, phone (encrypted), approval_status, approved_by
3. **`client_profiles`** — user_id, name, date_of_birth (encrypted), phone (encrypted), emergency_contact (encrypted JSONB), city, province
4. **`therapist_clients`** — therapist_id, client_id, status (ACTIVE/PAUSED/TERMINATED), UNIQUE(therapist_id, client_id)
5. **`worksheet_templates`** — title, type, schema (JSONB), scoring_config (JSONB), is_system, created_by, is_published, version
6. **`worksheet_assignments`** — template_id, therapist_id, client_id, instructions, due_date, status
7. **`worksheet_submissions`** — assignment_id, client_id, responses (encrypted JSONB), score (JSONB), finalized_at, integrity_hash (SHA-512), NO updated_at (immutable after finalization)
8. **`session_notes`** — therapist_id, client_id, session_date, session_type, all clinical text fields encrypted, status (DRAFT/FINALIZED), version
9. **`session_note_versions`** — session_note_id, version, content_snapshot (encrypted JSONB), changed_by
10. **`audit_logs`** — actor_id, action, resource_type, resource_id, details (JSONB), ip_address, user_agent — **append-only, no UPDATE/DELETE**
11. **`refresh_tokens`** — user_id, token_hash, expires_at, revoked_at

**Key constraints:**

- RLS on all clinical tables (therapist sees own clients only, client sees own data only)
- `audit_logs`: INSERT only, no UPDATE/DELETE for any role
- `worksheet_submissions`: UPDATE blocked when `finalized_at IS NOT NULL`
- All sensitive fields use AES-256-GCM field-level encryption
